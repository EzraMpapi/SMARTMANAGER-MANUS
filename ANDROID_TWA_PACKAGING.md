# Smart Manager Android Packaging Guide

## Delivery path

Smart Manager is a deployed React web application, so the appropriate native Android delivery path is a **Trusted Web Activity (TWA)**. A TWA opens the production Progressive Web App in a full-screen Android experience while the web application remains the single source of product logic and data. It does not duplicate ERP code into a separate mobile application.

| Item | Smart Manager value |
|---|---|
| Production origin | `https://bserp-dashbo-xgm6fauw.manus.space` |
| Web manifest | `https://bserp-dashbo-xgm6fauw.manus.space/manifest.webmanifest` |
| Application name | Smart Manager — Enterprise ERP |

| Android wrapper | Bubblewrap Trusted Web Activity |
| Store deliverable | Signed Android App Bundle (`.aab`) for Google Play; signed APK for direct device testing |

## Hosted-manifest verification

The managed production host injects its PWA manifest at `https://bserp-dashbo-xgm6fauw.manus.space/__manus/pwa/manifest.webmanifest`. The project-owned `manifest.webmanifest` remains in the release build and is covered by automated validation, but the hosted wrapper currently routes direct root static-file requests through its application shell. Before initializing Bubblewrap, use the injected hosted manifest route and verify its identity fields match the final Smart Manager application metadata.

> A TWA must be associated with a site the Android package is authorized to represent. The authorization is a Digital Asset Links file on the production origin, generated only after the final Android signing certificate is known.[1]

## Prerequisites

Install a supported JDK, Android SDK command-line tools, and Node.js. Bubblewrap can download missing Android dependencies during its first run when this is permitted. Use a dedicated release keystore owned and protected by the organization; do not commit keystores, passwords, or generated signing credentials to this repository.[2]

## Build steps

Run the following from an isolated packaging directory after the published site serves the web manifest:

```bash
pnpm dlx @bubblewrap/cli init \
  --manifest=https://bserp-dashbo-xgm6fauw.manus.space/manifest.webmanifest

# Confirm application ID: tz.smartmanager.erp
# Configure a release signing key when Bubblewrap prompts.

bubblewrap build
```

The generated Android project contains an APK suitable for installation testing. Configure the same release signing key and run Bubblewrap's bundle task to create the `.aab` required for Google Play submission. The Android project generated by Bubblewrap is a build artifact: keep it in a protected source repository or release pipeline rather than mixing generated Gradle files into the ERP web application source.[2]

## Domain verification

After the release keystore is created, obtain its SHA-256 certificate fingerprint from Bubblewrap or `keytool`. Create the following file at the exact production location `/.well-known/assetlinks.json`, replacing the placeholder only with the **final release certificate** fingerprint:

```json
[
  {
    "relation": ["delegate_permission/common.handle_all_urls"],
    "target": {
      "namespace": "android_app",
      "package_name": "tz.smartmanager.erp",
      "sha256_cert_fingerprints": ["REPLACE_WITH_RELEASE_SHA256_FINGERPRINT"]
    }
  }
]
```

Do not publish the placeholder file. It would be invalid and does not establish trust. Once the final value is available, add the production file, verify it over HTTPS, and use Bubblewrap validation before distributing the application.[1]

## Release checks

The release owner should verify that the TWA opens the production domain without a browser toolbar, authentication still returns to the dashboard, sign-out returns to the login experience, and common tablet and phone breakpoints remain usable. Upload the signed `.aab` to Google Play internal testing before production rollout. Keep the matching keystore safely stored: changing its signing identity prevents normal application updates.

## Verified test artifact

A signed **test APK** was compiled and package-verified from the generated TWA wrapper as `tz.smartmanager.erp`, version `2`, with launcher label **Smart Manager**. It is suitable for direct device installation and functional testing only. Its isolated sandbox signing key is intentionally not a production release key and must **not** be reused for Google Play. Before store distribution, create an organization-controlled release key, update the Digital Asset Links certificate fingerprint, build a signed `.aab`, and complete Play Console testing.
