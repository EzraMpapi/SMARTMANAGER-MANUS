04 / Event Classification

Classification & Dead-Letter Handling

Every leased event is strictly classified against the trusted outbound transaction. Only safe states are requeued for settlement; all others remain quarantined.

Safe for Settlement
SAFE_RETRY
Transient or non-terminal provider state. Safe to requeue and re-evaluate through the idempotent service path.
SAFE_RECONCILE
Terminal provider status matches the trusted outbound identity, amount, and currency. Safe to finalize settlement.
Quarantined / Dead-Letter
CONFLICT
Durable provider identity conflict. A reused provider reference with a different semantic fingerprint.
FIELD_MISMATCH
Amount, currency, or provider reference does not match the trusted outbound transaction record.
UNCORRELATED
Missing client reference or the trusted outbound transaction could not be found in the tenant scope.
ALREADY_SETTLED
The trusted transaction or bank posting is already terminal. No further action is permitted.
Exact Replays
Exact semantic duplicates are marked DUPLICATE and never reposted. They do not consume settlement caps.
